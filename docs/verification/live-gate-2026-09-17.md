## Finding: S09 read the wrong event key

`test_s09_omission_passes_citations_but_fails_coverage` indexed
`event["kind"]`; `cafe/report.py` emits `"type"` (and all validators already
use `event.get("type", "")`). The stub shift produces zero events, so CI never
touched the lookup; the first live shift logged a real allergen check and
raised `KeyError`. Fixed to the module's own defensive idiom
(`str(event.get("type", "")).startswith("safety")`); after the fix the live
run exercises the branch it guards (coverage validator flags the dropped
`safety-t4-1` event twice). Stub execution, marimo strict/canonical gates,
and the offline suite are unchanged and green.
